For this intermediate submission, I've been able to implement a working subset of both the Lexical and the Syntax Analyzer. The idea was to get the very basics of the "core logic" down, so that we should be able to parse the given "input.txt" sample code correctly without concern for the whole complicated grammar just yet.

On the Lexical Analyzer side (in "lex_analyzer.l"), I configured regular expressions and semantic actions for the recognition of most indispensable elements. This includes basic keywords such as "int", "return", "if", "else", and "printf". I also got it to do recognizing of standard variables (IDs) and integer constants (CONST_INT). Alongside that, the lexer knows how to tokenize all the required operators and punctuators such as assignment, math operators ("*", "/", "%", "+", "-"), relational comparisons ("<", "==" etc), parenthesis, curly braces, and semicolons.

Over in the Syntax Analyzer ("syntax_analyzer.y"), I mapped out those tokens and began to build the core grammar rules. I've got the basic structure working, things from the main program and function definitions right down to the different statement blocks. It is able to deal with returning values, printing, and branching using if-else logic. I have also expanded the expressions to deal with mathematical operations and logical comparisons properly. Finally, I connected the semantic actions so that every time a rule corresponds, I log the parse tree directly into "my_log.txt" step-by-step.
